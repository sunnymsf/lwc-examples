### Overview

The input counter represents the `number` input type.

### Use Cases

Input Counter lets the user increase and decrease the numberical value of an input field.

### Non-goals

- Complex or composite inputs.
- Counters that feature non-numerical values such as a spinbox.
- Customizations can be made through Styling Hooks and `::part` API, where the addition of CSS through ::part falls outside the support matrix of SDS.
- Variants are not included in SDS. Variants should be applied at the subsystem layer.

### Features

- The API design of the SDS Input Counter is specific to the [HTML Input type=number](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/number) element.
- Only numbers are accepted as values.
- Configurable minimum and maximum ranges.
- Configurable step value.
- Customizable step up and step down labels.
- The default appearance provides the basic structure of th component.
- The default appearance comes unbranded.
- Styling Hooks should be used to customize the appearance.
- Customization beyond Styling Hooks can be achieved through the CSS Shadow Parts API.

---

### API

The API design that follows _only_ applies to the [HTML Input type=number Element](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/number).

### Custom Element

This specification will apply to a SDS custom element but can also be implemented in a subsystem's ecosystem with the subsystems namespace used as the prefix to the custom elements definition:

1. `sds-input-counter` - This is owned by the Salesforce Design System (SDS) Team.
2. `<namespace>-input-counter` - This is owned by a subsystem built on SDS, e.g. `dxp-input-counter`

### Anatomy and Appearance

#### DOM Structure

```html
<host>
  <div part="input-counter">
    <div part="label-container">
      <slot name="label-start"></slot>
      <label part="label">
        <slot name="label"></slot>
      </label>
      <slot name="label-end"></slot>
    </div>
    <div part="input-container">
      <slot name="start"> </slot>
      <input part="input" />
      <button part="step step-down">
        <slot name="step-down"> </slot>
      </button>
      <button part="step step-up">
        <slot name="step-up"> </slot>
      </button>
      <slot name="end"> </slot>
    </div>
  </div>
  <div part="help-text">
    <slot name="help-text"></slot>
  </div>
</host>
```

#### Slots

| Slot Name     | Description                                                                                              | Fallback Content |
| ------------- | -------------------------------------------------------------------------------------------------------- | ---------------- |
| `label`       | Text content that describes the input                                                                    | empty            |
| `label-start` | Content placed before the label                                                                          | empty            |
| `label-end`   | Content placed after the label                                                                           | empty            |
| `start`       | Content placed before the user-added number, such as an icon                                             | empty            |
| `end`         | Content placed after the user-added number, such as an icon                                              | empty            |
| `step-up`     | Content label for the step up button                                                                     | `svg`            |
| `step-down`   | Content label for the step down button                                                                   | `svg`            |
| `help-text`   | Content area for additional text, such as examples of the type of required data entry, or error messages | empty            |

#### Parts

| Part Name         | Description                                                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `input-counter`   | Enables styling for the entire component beyond Styling Hooks, falls outside the support matrix of SDS                               |
| `input-container` | Enables styling for the container of the input and corresponding `start` and `end` slots, falls outside of the support matrix of SDS |
| `input`           | Enables styling for the input itself beyond Styling Hooks, falls outside the support matrix of SDS                                   |
| `label`           | Enables styling for the label beyond Styling Hooks, falls outside of the support matrix of SDS                                       |
| `label-container` | Enables styling for the label container, falls outside of the support matrix of SDS                                                  |
| `step`            | Enables styling of the stepping buttons beyond Styling Hooks, falls outside the support matrix of SDS                                |
| `step-down`       | Enables styling of the step down button beyond Styling Hooks, falls outside the support matrix of SDS                                |
| `step-up`         | Enables styling of the step up button beyond Styling Hooks, falls outside the support matrix of SDS                                  |
| `help-text`       | Enables styling of the help text beyond Styling Hooks, falls outside the support matrix of SDS                                       |

#### Properties & Attributes

The following properties and attributes are derived from the [HTML Input type=number specification](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/number):

| Attribute       | Type               | Default Value               | Description                                                                       |
| --------------- | ------------------ | --------------------------- | --------------------------------------------------------------------------------- |
| `disabled`      | `bool`             | `false`                     | Whether the control is disabled                                                   |
| `form`          | `string`           |                             | ID of the form to associate with the input                                        |
| `invalid`       | `bool`             | `false`                     | Validity state of the input                                                       |
| `min`           | `number`           |                             | The minimum valid value                                                           |
| `max`           | `number`           |                             | The maximum valid value                                                           |
| `name`          | `string`           |                             | Name of the element to use for form submission                                    |
| `placeholder`   | `string`           |                             | User-visible label to be placed within the control                                |
| `readonly`      | `bool`             | `false`                     | Whether to allow the value to be edited by the user                               |
| `required`      | `bool`             | `false`                     | Whether the control is required for form submission                               |
| `step`          | `number`, `string` | `1`                         | The granularity that the value must adhere to; `any` means no stepping is implied |
| `stepDownLabel` | `string`           | `Decrease value by {step}`  | Label of the step down button for assistive devices                               |
| `stepUpLabel`   | `string`           | `Increaser value by {step}` | Label of the step up button for assistive devices                                 |
| `value`         | `string`           |                             | Initial value of the control                                                      |

### Behavior

#### States & Interactions

| State Group | States         | Initial State | Description                                                                                                                          |
| ----------- | -------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `active`    | `true/false`   | `false`       | Indicates the input has been interacted with                                                                                         |
| `disabled`  | `true`/`false` | `false`       | Indicates whether the input is disabled and cannot be interacted with. When disabled, the control is not included in form validation |
| `readonly`  | `true`/`false` | `false`       | Controls whether or not the user can edit the form control                                                                           |
| `invalid`   | `true`/`false` | `false`       | Displays a style when the provided text does not meet the `pattern` Regular Expression requirements                                  |
| `valid`     | `true`/`false` | `true`        | Displays a style when the provided text meets the `pattern` Regular Expression requirements                                          |

### Accessibility

#### Global Attributes

All [global `aria-*` attributes](https://www.w3.org/TR/wai-aria-1.1/#global_states) should follow all [interaction requirements](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/number) per the W3C.

#### Label Focus

When interacting with the associated label via click, it should focus the related input.

#### Role

The implicit role for the input-counter is spinbutton. If spinbutton is not an important feature for your form control, consider using another component.

### Internationalization

All elements of the input control (e.g., `start`/`end` slots, user-entered text, icons, etc) should adhere to bi-directional languages such as `ltr` (left to right) and `rtl` (right to left).

### Open Questions

- Update test plan when standardized.
