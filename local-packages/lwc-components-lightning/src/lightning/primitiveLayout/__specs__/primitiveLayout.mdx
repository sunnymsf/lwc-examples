
### Overview

The SDS layout provides a flexible, mobile-first, device-agnostic layout system. It has baked-in support for responsive and RTL layouts, based on the [CSS Flexbox][flexbox] and [CSS Grid][grid] specifications.

### Use Cases

The use of SDS layout is recommended for providing structure and alignment of content. This can be leverage within a component, typically using Flexbox or Grid, or within a page layout, typically using Grid. The layout component can be used to create a variety of layouts, including:
- stacked or inline layouts, e.g. a form
- responsive layouts, e.g. a form with a stacked layout on mobile and an inline layout on desktop
- grid layouts, e.g. a dashboard
- responsive grid layouts, e.g. a dashboard with a 2 column layout on mobile and a 4 column layout on desktop
- nested layouts, e.g. a dashboard with a 2 column layout on mobile and a 4 column layout on desktop with a 2 column layout in the first column and a 2 column layout in the second column

### Non-goals

- Even thought the layout component can be used to create a variety of layouts, it does not support the entire specification of Flexbox and Grid. It is not intended to be a replacement for CSS Flexbox and CSS Grid, but rather a subset of the specification that is commonly used in layouts.ß

### Features

- Flexbox and Grid based layouts
- Spacing options to define gaps, including option to pass in custom value
- Alignment options for inline and block axis
- Nested flexbox and grid layouts
- LTR/RTL directional support
- Flexbox layouts, including:
  - 1-6 and 12 column layout support
  - Horizontal and vertical layouts
  - Flow options to wrap to new line or inflexible
  - Order options
- Grid layouts, including:
  - 12 column layout
  - Custom grid layouts
  - Grid regions, span and offset

### API

The layout component is based on the [CSS Flexbox][flexbox] and [CSS Grid][grid] specifications.

#### Custom Element

This specification will apply to a SDS custom element but can also be implemented in a subsystem's ecosystem with the [subsystems namespace][namespace-service] used as the prefix to the custom elements definition:

1. `sds-layout` - This is owned by the Salesforce Design System (SDS) Team.
2. `<namespace>-layout` - This is owned by a subsystem built on SDS, e.g. `dxp-layout`

### Anatomy and Appearance

The following DOM structure and named part attribute on the leaf node as documented is required to use the SDS Layout CSS.

#### DOM Structure

```html
<host>
  <div part="layout">
    <slot></slot>
  <div>
</host>
```

#### Slots

| Slot Name | Description | Fallback Content |
| - | - | - |
| default | The content within a layout region | empty |

#### Parts

| Part Name | Description |
| - | - |
| `layout` | The container for the layout region |

### Internationalization

All slotted content inside the layout component will adhere to bi-directional languages such as `ltr` (left to right) and `rtl` (right to left).
